# Cellendar 관리자 배포 안내

## 1. Microsoft Entra 앱 등록

1. Microsoft Entra 관리 센터에서 **앱 등록 → 새 등록**을 선택합니다.
2. 여러 조직 사용자를 받으려면 **모든 조직 디렉터리의 계정**을 선택합니다.
3. 개인 Microsoft 계정까지 로그인 대상으로 표시하려면 개인 계정 지원 옵션을 선택할 수 있지만, Excel 동기화는 Microsoft Graph Excel API를 지원하는 Microsoft 365/OneDrive 환경에서 검증해야 합니다.
4. **인증 → 플랫폼 추가 → 단일 페이지 애플리케이션(SPA)**을 선택합니다.
5. 아래 URI를 등록합니다.
   - 개발: `http://localhost:8080/app/`
   - 배포: `https://GITHUB_ID.github.io/REPOSITORY_NAME/`
6. Microsoft Graph 위임 권한 `User.Read`, `Files.ReadWrite`를 추가합니다.
7. 애플리케이션(클라이언트) ID를 복사합니다.

클라이언트 암호는 만들거나 PWA에 넣지 않습니다. PWA는 Authorization Code + PKCE를 사용합니다.

## 2. 앱 설정

`app/config.js`에서 다음 값을 수정합니다.

```js
clientId: '발급받은 클라이언트 ID',
tenantId: 'common'
```

여러 조직 계정을 지원할 때 `common`을 사용합니다. 특정 조직 전용이면 그 조직의 테넌트 ID를 입력합니다.

## 3. GitHub Pages 게시

1. GitHub에 새 저장소를 만들고 이 프로젝트를 올립니다.
2. 저장소 **Settings → Pages**로 이동합니다.
3. **GitHub Actions**를 선택합니다.
4. `main` 브랜치에 올리면 포함된 `.github/workflows/pages.yml`이 `app` 폴더만 자동 게시합니다.
5. Actions의 배포가 끝난 뒤 발급된 HTTPS 주소를 Entra SPA 리디렉션 URI와 정확히 일치시킵니다.

## 4. 사용자 배포

1. `outputs/cellendar/캘린더(자동).xlsx`를 사용자에게 제공합니다.
2. 사용자는 자기 OneDrive에 `Cellendar` 폴더를 만들고 파일을 `Cellendar/캘린더(자동).xlsx`로 저장합니다.
3. GitHub Pages 주소 또는 QR 코드를 전달합니다.

## 보안 및 운영

- 저장소에는 암호, 토큰, 사용자 Excel 파일을 올리지 않습니다.
- 클라이언트 ID는 공개 식별자이며 PWA에 포함할 수 있습니다.
- Graph의 `429` 응답은 앱이 대기 후 한 번 재시도합니다.
- 앱이 보이는 동안 5분마다 동기화하며, 일정 저장·삭제 후에도 동기화합니다.
- 공개 배포 전 개인정보 처리 안내와 문의 연락처를 추가하는 것을 권장합니다.
